# 1주차

## 1. TCP와 UDP를 설명하시오.
- 둘 다 데이터를 전송하는 프로토콜
- TCP는 연결을 먼저 맺고 데이터를 주고받는 방식
- TCP는 신뢰성이 높지만 속도가 느린 편
- UDP는 연결 과정 없이 데이터는 전송하는 방식
- UDP는 빠르지만 도착 여부나 순서를 보장하지 않는다.
  
## 2. GET과 POST의 차이를 설명하시오.
- 둘 다 HTTP 요청 방식이다.
- GET은 데이터를 조회할 때 사용
- POST는 데이터를 보내서 처리할 때 사용
- GET은 데이터를 URL 뒤에 붙여서 보내기 때문에 주소창에 노출되고 길이 제한도 있다.
- POST는 요청 바디에 데이터를 담아서 보내기 때문에 노출되지 않고 길이 제한도 없다.

## 3. TCP 3,4 Handshake를 설명하시오.
- 3 Handshake: TCP 연결을 맺는 과정
- 1. 클라이언트가 서버에게 연결을 위한 SYN을 보낸다.
  2. 서버가 받고 준비되었다는 의미의 SYN과 ACK를 보낸다.
  3. 마지막으로 클라이언트가 다시 ACK를 보내면 연결 완료.
- 4 Handshake: 연결을 끊는 과정
- 1. 클라이언트가 연결 종료를 위한 FIN을 보낸다
  2. 서버가 ACK로 답을 한다.
  3. 서버도 마무리되면 FIN을 보낸다.
  4. 클라이언트가 마지막으로 ACK를 다시 보내서 연결 종료 한다.

## 4. DNS의 동작 과정에 대해 설명하시오.
- IP주소를 도메인 이름으로 변경해주는 시스템
- 도메인 이름을 입력하면 캐시가 있는지 확인 하고 없을 경우 DNS서버에게 물어본다.
- 로컬 DNS, 루트 DNS, 최상위 도메인 서버에 차례대로 물어보면서 IP주소를 가져온다.

## 5. 사용자가 브라우저에 URL을 입력한 후 웹 페이지가 표시되기까지의 과정을 설명하시오.
- URL을 입력하면 DNS를 통해 도메인의 IP주소를 찾는다.
- 해당 서버와 TCP 3Handshake 연결을 맺는다.
- 서버는 요청에 맞는 응답을 보내준다.
- 브라우저가 요청을 받아서 파일들을 받고 화면에 렌더링 한다.

## 6. ARP의 역할과 동작 과정에 대해 설명하시오.
- IP주소로 실제 통신에 필요한 MAC주소를 알아내는 프로토콜
- 상대의 MAC 주소를 모를 때 해당 IP를 브로드캐스트한다.
- 해당 IP를 가진 장비가 MAC 주소를 알려준다.

## 7. HTTP와 HTTPS의 차이에 대해 설명하시오.
- HTTP는 데이터를 암호화하지 않고 HTTPS는 암호화를 적용한다.
- 보안때문에 사용하며 대부분의 사이트가 HTTPS를 사용한다.

## 8. IP 주소와 MAC 주소의 차이에 대해 설명하시오.
- IP주소는 논리적인 주소로 변경될 수 있다.
- MAC주소는 장비에 물리적으로 부여된 주소로 변하지 않는다.
- 통신할 땐 IP주소로 방향을 잡고 MAC주소로 정확한 장비를 찾는다. 

## 9. 공인 IP와 사설 IP의 차이에 대해 설명하시오.
- 공인IP는 세계적으로 고유한 주소로 외부에서 직접 접근 가능하다.
- 사설IP는 집, 회사 등에서 내부 네트워크 안에서 사용하는 주소로 네트워크 밖에서는 접근할 수 없다.
