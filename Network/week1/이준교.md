# 1주차

## 1. TCP와 UDP를 설명하시오.

- TCP와 UDP는 전송 계층 프로토콜이며, 가장 큰 차이는 신뢰성 보장 여부입니다.
- TCP는 연결 지향형 프로토콜이며, 데이터를 보내기 전에 먼저 연결을 수립하고, 데이터 전송 과정에서 패킷 순서 보장, 재전송, 흐름제어 및 혼잡 제어를 통해 신뢰성 있는 통신을 제공합니다.
- UDP는 비연결형 프로토콜이며, 별도의 연결 과정 없이 데이터를 빠르게 전송하고, 순서 보장이나 재전송을 하지 않습니다.

## 2. GET과 POST의 차이를 설명하시오.

- GET과 POST는 모두 HTTP 메서드이지만, 용도와 의미가 다릅니다.
- GET은 리소스를 조회할 때 사용하며, POST는 리소스를 생성하거나 서버 상태를 변경할 때 사용합니다.
- GET은 요청 데이터를 보통 URL의 쿼리 스트링에 담아서 보내고, 서버 상태를 바꾸지 않는 조회 용도이기 때문에 멱등성과 안정성을 가집니다. 또, 캐싱도 가능합니다.
- POST는 데이터를 body에 담아 보내기 때문에 URL에 노출되지 않고, 길이 제한도 자유롭습니다. 같은 요청을 여러 번 보내면 중복 생성 같은 문제가 발생할 수 있습니다.

## 3. TCP 3,4 Handshake를 설명하시오.

- 3-way handshake는 클라이언트와 서버가 연결을 수립하는 과정이며, 4-way handshake는 연결을 종료하는 과정입니다.
- 3-way handshake는 
    - 클라이언트가 SYN 패킷을 보내 연결을 요청합니다.
    - 서버는 요청을 받고, 수락한다는 의미로 SYN-ACK 패킷을 클라이언트에게 전달합니다.
    - 클라이언트가 다시 ACK을 서버에 보내면 연결이 성립됩니다.
- 단순히 한쪽이 요청만 보내는 것으로 끝나는 것이 아니라 서로 송수신이 가능한 상태인지 확인하기 위해서 3번이 필요합니다.
- 4-way handshake는
    - 먼저 끊으려는 쪽이 FIN을 보내서 연결 종료 의사를 전달합니다.
    - 상대가 ACK를 보내고, 종료 요청을 확인합니다. 이때는 아직 상대가 보낼 데이터가 남아있을 수 있기 때문에 연결이 반쪽만 닫힌 상태입니다.
    - 상대도 데이터를 다 보내고 나면 FIN을 보내 연결 동료 의사를 전달합니다.
    - 마지막으로 ACK를 보내면 연결이 완전히 종료됩니다.

## 4. DNS의 동작 과정에 대해 설명하시오.

- DNS는 사람이 읽는 도메인 이름을 실제 IP 주소로 변환해주는 시스템입니다.
- 브라우저에 도메인을 입력하면 먼저 캐시부터 확인합니다.
- 브라우저 캐시, OS 캐시, 로컬 DNS 서버 순서로 확인하며, 캐시에 없으면 본격적으로 조회가 시작됩니다.
- 조회 요청은 로컬 DNS 서버가 계층적으로 물어봅니다.
    - 루트 네임서버에 물어보면, TLD 서버 주소를 획득할 수 있습니다.
    - TLD 네임서버는 권한 있는 네임 서버를 알려주고,
    - Authoritative 네임서버가 실제 IP 주소를 응답합니다.

## 5. 사용자가 브라우저에 URL을 입력한 후 웹 페이지가 표시되기까지의 과정을 설명하시오.

- `google.com`이라고 가정
- 브라우저가 google.com의 IP를 알아내기 위해 DNS 조회를 수행합니다.
- 캐시를 확인하고, 없으면 루트, TLD, 권한 네임서버 순으로 IP 주소를 받아옵니다.
- IP 주소를 가진 서버와 TCP 3-way handshake로 연결을 맺습니다. HTTPS를 사용하기 때문에 TLS handshake를 인증서를 검증하고 암호화 키를 교환합니다.
- 연결이 되면 브라우저가 HTTP 요청을 보냅니다. 서버는 요청을 처리한 뒤에 HTML 문서를 응답으로 반환합니다.

## 6. ARP의 역할과 동작 과정에 대해 설명하시오.

- ARP는 IP 주소를 실제 MAC 주소로 변환해주는 프로토콜입니다.
- 같은 로컬 네트워크 안에서 통신할 때, IP 주소는 알지만 실제로 프레임을 보내려면 상대의 MAC 주소가 필요합니다.
- A가 B에게 데이터를 보내려는데 B의 MAC을 모르면, 먼저 ARP Request를 브로드캐스트합니다.
- 같은 네트워크의 모든 장비가 이 요청을 받지만, 해당 IP의 주인인 B만 ARP Reply를 유니캐스트로 응답합니다.
- A는 이 MAC 주소를 ARP 테이블에 저장해두고, 실제 프레임을 B에게 보냅니다.

## 7. HTTP와 HTTPS의 차이에 대해 설명하시오.

- 가장 큰 차이는 암호화 여부입니다.
- HTTP는 데이터를 평문으로 주고받기 때문에, 중간에서 패킷을 가로채면 내용이 그대로 노출됩니다.
- HTTPS는 통신 전에 TLS handshake를 거쳐서 기밀성, 무결성, 인증을 보장합니다.
- HTTP는 80번 포트, HTTPS는 443번 포트를 사용합니다.
- handshake를 할 때 비대칭키로 안전하게 대칭키를 교환하고, 실제 데이터 통신은 빠른 대칭키로 암호화합니다.

## 8. IP 주소와 MAC 주소의 차이에 대해 설명하시오.

- IP 주소와 MAC 주소는 둘 다 통신을 위한 주소지만, 계층과 역할이 다릅니다.
- MAC 주소는 2계층(데이터링크) 주소로, 네트워크 장비에 물리적으로 부여된 고유 주소입니다. 변하지 않고, 같은 네트워크 안에서 실제로 프레임을 주고받을 때 사용됩니다.
- IP 주소는 3계층(네트워크) 주소로, 네트워크 환경에 따라 할당되는 논리적 주소입니다. 어느 네트워크에 속했는지에 따라 바뀌고, 서로 다른 네트워크 간 라우팅, 즉 목적지까지의 경로를 찾아가는 데 사용됩니다.

## 9. 공인 IP와 사설 IP의 차이에 대해 설명하시오.

- 공인 IP와 사설 IP의 차이는 인터넷에서 직접 식별 가능한지 여부입니다.
- 공인 IP는 ISP가 할당하는, 인터넷상에서 전 세계적으로 유일한 주소입니다. 외부에서 직접 접근할 수 있어서 서버처럼 외부에 서비스를 제공하는 장비에 사용합니다.
- 사설 IP는 내부 네트워크에서만 쓰는 주소입니다. 외부 인터넷에서는 직접 접근할 수 없고, 내부에서만 유일하면 됩니다. 그래서 서로 다른 내부망끼리는 같은 사설 IP를 사용해도 문제가 없습니다.
- 이 둘을 연결해주는 게 NAT입니다. 내부 장비들의 사설 IP를 공인 IP로 변환해서 외부와 통신하게 합니다.
